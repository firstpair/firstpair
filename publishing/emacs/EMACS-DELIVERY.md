# FirstPair Emacs Bundle Contract

A FirstPair Emacs bundle is a directory. It is generated by `firstpair-emacs
build` from a title's `vault.build.json`, sealed by a manifest, and delivered
as a ZIP. This document is the contract every bundle satisfies; the reader
(`lisp/`), the verifier (`firstpair-emacs validate`), and the publisher rely
on it.

## Layout

```text
<bundle>/
  init.el                      loader: registers the bundle; uses an installed reader if present
  install.sh                   copies the manuals into an Info directory (install-info or Emacs)
  dir                          Info directory node listing both manuals
  <stem>.info                  the book, one Info file
  <stem>-refs.info             the references, one Info file
  texi/<stem>.texi             Texinfo source of the book
  texi/<stem>-refs.texi        Texinfo source of the references
  Guide.md, README.md          the complete first-use manual (identical bytes)
  lisp/firstpair-bundle.el     bundle loader and index access
  lisp/firstpair-lexicon.el    offline dictionary
  lisp/firstpair-reader.el     the reading mode
  data/bundle.json             bundle description (schema firstpair-emacs-bundle-v1)
  data/reader.json             ordered reader pages: id, title, node, part
  data/records.json            records and evidence targets: id, label, kind, section, node, rights, file, quotedIn
  data/references.json         every cross-reference each node contains, per manual
  data/marked.tsv              words the dictionary window explains, by position
  lexicon/LEXICON.json         lexicon description (schema firstpair-lexicon-v1)
  lexicon/entries.tsv          id, headword, part, code, frequency, senses
  lexicon/forms.tsv            form, entry, features, enclitic
  lexicon/stems.tsv            stem, entry, index
  lexicon/endings.tsv          ending, part, declension, variant, stem, features, order, frequency
  evidence/                    delivered evidence files, named by target id
  FIRSTPAIR-EMACS-MANIFEST.json sealed inventory (schema firstpair-emacs-manifest-v1)
```

`<stem>` is `emacs.direntry.name`, by default the title slug; a preview
bundle uses `<stem>-preview`, so a preview and a complete edition can share
an Info directory.

## Info conventions

- Both files are written directly by `firstpair_emacs.infowriter`, not by
  `makeinfo`, so the output is byte-reproducible for a given source revision
  and the builder knows the exact line and column of every marked word.
- Node names contain no comma, colon, parenthesis, or period. A colon becomes
  ` -` and a period becomes `-`; `Letters to Atticus 4.8a` is the node
  `Letters to Atticus 4-8a` while its title and its citation label keep the
  period.
- The reader manual's Top node lists: a Contents node naming every chapter in
  reading order; one node per part (or the chapters directly when the title
  declares no parts); the guide node; the colophon.
- The references manual's Top node lists one section per record set (its
  `section`), an Evidence section when the title declares evidence targets,
  and the glossary when a lexicon is present.
- A citation in the text is written after the quoted words as
  `(*note Label: (<stem>-refs)Node,)`. The comma terminator is hidden by Info
  readers, so the citation reads "(see Label)". The reader hides the manual
  name as well.
- Chapter headings carry `Ref:` anchors named `<page id>-<heading slug>`.
- Footnotes are rendered at the end of their node under a `Footnotes` rule and
  referenced as `(1)`, `(2)`, ... in the text.

## marked.tsv

One row per word the dictionary window will underline:

| column | meaning |
| --- | --- |
| manual | manual stem |
| node | node name |
| line | 1-based line within the node, counting the `File:` header line as 1 |
| column | 0-based character column |
| length | length of the word in characters |
| form | the normalised form (lower case, `v`→`u`, `j`→`i`, no diacritics) |
| entries | comma-separated lexicon entry ids, best reading first |

The reader locates each word by line and column and confirms the text there
normalises to `form`; when Info has moved the text it searches the same line
for the word.

## Lexicon

The lexicon is a projection: with `mode: projected` the bundle ships only the
entries and analysed forms the delivered text uses plus the complete ending
table, so unlisted words are still analysed from stems and endings; with
`mode: complete` it ships every entry and no per-form index. Upstream corpora
are pinned by digest in `lexicon/<language>/SOURCES.json` inside FirstPair and
cached under `~/.cache/firstpair/lexicon/`; `firstpair-emacs lexicon` fetches
or verifies them. FirstPair's own supplement rows are recorded with their
reason.

## The reader as a package

`lisp/` is also the source of the standalone `firstpair-reader` package.
`firstpair-emacs package` assembles `dist/firstpair-reader-<version>/` and
`dist/firstpair-reader-<version>.tar` — the three Lisp files, a
`firstpair-reader-pkg.el`, and the shared handbook compiled as the package's
own Info manual with its `dir` — for `M-x package-install-file`.
`package-vc-install` with `:lisp-dir "publishing/emacs/lisp"` installs the
same files from the repository. Every file's `;; Version:` header must agree;
the package version is the reader's. Bundles keep shipping `lisp/`, appended
to `load-path` so an installed package wins when both are present; the
bundle schema (`firstpair-emacs-bundle-v1`) is the compatibility contract
between them.

With the package installed, `firstpair-reader-bundle-directories` lists the
folders `firstpair-read` searches for bundles, and
`firstpair-reader-install-info` / `install.sh` put a bundle's manuals into an
Info directory (`~/.local/share/info` by default) so plain `info` and `C-h i`
list them.

## Guarantees

- Everything works offline; no file in the bundle contacts a network.
- No symlinks, Git metadata, caches, compiled Lisp, or personal files ship.
- The two Info files and the two Texinfo files are written from one document
  model; they cannot describe different books.
- Rights are enforced at build: `restricted` evidence is delivered as
  metadata only, never as bytes.
- `FIRSTPAIR-EMACS-MANIFEST.json` binds source revision, product, edition,
  counts, unmatched citation anchors, and the SHA-256 of every file.

## Verification

```sh
~/src/firstpair/publishing/scripts/firstpair-emacs validate --bundle <bundle>
```

checks the sealed inventory, parses both Info files structurally, resolves
every pointer, menu entry, and cross-reference inside the bundle, verifies the
lexicon table digests, compiles both Texinfo sources with `makeinfo` when it is
installed, and opens every node in `emacs --batch` with the reader loaded to
confirm every marked word is found and every reference resolves.
