# FirstPair Triptych

An Obsidian plugin for the *Lighthouse Republics* vault. It renders the
fenced ` ```triptych ` JSON blocks generated by
`scripts/build-obsidian-triptychs.py` as side-by-side Rosetta panes — one
column per edition — instead of a wall of raw JSON.

The vault Home note opens a dedicated full-width **Triptych Reader**, with a
peer **Review** surface in the same leaf. Their top navigation stays pinned.
Review lists every touched Reader page and renders a deterministic editorial
digest; it never assembles or overwrites a manuscript. The Reader's
single pinned top rail is ordered **Previous · Up · Back · Top · TOC · Next**.
The set contents and fragment views replace the ordinary Markdown note in the
same leaf, while only the prose area scrolls. Back restores the prior Reader
location and scroll position. The Reader's compact JSON index contains only
navigation and immutable version/commit identity; every pane and review
payload is read lazily from the existing fenced triptych note, so the vault
stores no second copy of the compared prose. Reader schema 4 binds every page
to a project-neutral editorial target contract and one `source_content_id`.
It names the final listed
edition as the navigation edition and assigns every monotonically ordered Part
a stable `partId` independent of its editable display title. Up follows
fragment → part → set → contents, and each part TOC marks the current fragment. `Reader.md`,
`Contents.md`, set hubs, and fragment notes remain complete Markdown fallbacks
when community plugins are disabled; fragments repeat
Previous/Up/Top/TOC/Next above and below, with Up linked to the exact
containing Part heading on the set hub.

Each pane carries the **Rosetta editorial rail** — bar marks (`·` shared,
`❘` tonal/lexical pressure, `❘❘` addition/omission/new claim, `❘❘❘` review
outlier, dotted edge for structural split/fuse), the 0-100 divergence
score, and the N/M/S/R/E/C/F feature vector, the same vocabulary as the
scored Rosetta Kindle EPUBs. A top banner marks fragments where two or
more panes are identical. Pane chips above each fragment (and the plugin
settings tab) toggle editions **globally** — hide a pane once and it is
hidden in every triptych. Views containing a triptych release the
readable-line-width clamp so the columns use the whole window; on narrow
screens the panes scroll horizontally like the Kindle Rosetta tables
instead of stacking.

The visible interface speaks the vault's language. On load the plugin reads
`Lighthouse Republics/_data/editions.jsonl` and takes the canonical
edition's `lang` (`en`, `it`, or `ru`; anything else, or an unreadable
ledger, falls back to English). Navigation, Review, pane controls, phrase
and correction dialogs, notices, settings, and command names come from the
`UI_STRINGS` table in `review-state.js`; counts agree with their noun
(Russian 1 фрагмент, 3 фрагмента, 5 фрагментов). Ledger fields, CSS classes,
icon keys, and the `EDITING-INSTRUCTIONS.md` digest stay English in every
vault, so decisions remain portable between languages and the mobile reader.

Beyond the triptychs, the plugin enhances the vault's other generated
notes in Reading view (each switchable in settings; switch to Editing /
source mode to read the raw generated note):

- **Transformation notes** render as side-by-side Before | After with
  word-level diff highlighting (deletions struck on the left, insertions
  marked on the right) under a badge rail: kind, cardinality, similarity
  meter, moved flag, and alignment method.
- **Lineage notes** render as a chain strip of edition chips — consecutive
  identical members collapse into runs ("South 2.0 → 2.2.1 ×6"), colored by
  change intensity — followed by one card per distinct state with a
  *diff vs previous* toggle, so a forty-member lineage reads as its handful
  of actual states.
- **Comparison hubs** gain lazy incipit previews: as rows scroll into view,
  each bare lineage ID is annotated with its opening words and member count.

Comparison sets are configured in `book/obsidian/triptych-sets.json` (any
number of editions per set — a pair such as South 2.2.1 First vs Final is
one entry); rerun `scripts/build-obsidian-triptychs.py` after editing it.

Each pane also carries a **prefer this** checkbox (mutually exclusive
across the panes of one fragment), and each fragment a compact **editing
note** field. For finer review:

- **Sentence & words** is a page-local toggle, off by default. It reveals an
  independent preference checkbox and a **Words** button beside every prose
  sentence (and any heading unit, marked with a **Heading** badge). Sentence
  choices are deliberately not forced into mutually exclusive groups because
  split and fused variants do not provide trustworthy one-to-one alignment.
- **Words** exposes builder-owned Unicode word tokens. Check adjacent words,
  use **Only** for one word, or select **Whole sentence**, then record
  **Good**, **Bad**, or **Edit**. Start another selection at any time: saved
  phrases may overlap and each remains independently editable.
- **Edit** records correction variants. An existing edit offers **Save &
  replace** or **Save next**; all variants remain stacked beneath the action
  row and one preferred variant is selected with a checkbox. Click a saved
  mark or saved-phrase row to reopen those controls.
- **Note** and **🎙 Voice** attach a span note to the selection: a typed
  note, any number of recordings, or both. Voice opens the note already
  recording. **■ Stop** writes the audio to `Preferences/voice/<note>/<clip>`
  (AAC/MP4 on iOS, Opus/WebM on desktop), reads it back byte for byte, and
  only then records it in the ledger's `span_notes` with its size, duration,
  and SHA-256. Closing the note mid-take stops and saves it.
- Transcription follows the saved recording and is stored beside it; it never
  replaces the audio. **Settings → Voice notes** picks the engine: local
  `mlx_whisper` on a Mac (default `mlx-community/whisper-large-v3-turbo`), an
  OpenAI-compatible `/audio/transcriptions` endpoint, both (local first), or
  off. Recordings made where no engine is available stay *pending*; the Mac
  transcribes them when the synced ledger arrives, and the command
  **Transcribe pending voice notes** retries all of them, failed ones
  included. The digest lists each voice note with its path and transcript.

**One edition.** The **Edition** menu above every triptych (and the
**Single-edition editing** setting) shows one edition alone. That page is for
editing, not comparing: no pane preference, no divergence rail or legend, the
sentence and word controls open, and the ordinary readable line width.

**On a phone.** Panes form a horizontal snap track with edition tabs that
follow taps and swipes; the tapped edition becomes the first pane on every
page. In **Words** there are no checkboxes: tap whole words, or press one and
drag across its neighbours, to select a phrase. Every saved phrase or note has
its own **Change** and **Remove**.

**Saved spans are coloured.** Up to three spans may overlap. Spans that
overlap get different colours, and a word inside several is striped; spans
that do not touch share a colour. A note with a recording is a voice span and takes its
own palette (green, pink, yellow, with a green underline), so voice notes
stand apart from text notes and phrase marks. Tap a coloured word to reopen its span, or
choose among the spans when it lies in more than one. The word picker, the
colours, and the overlap limit come from `shared/span-editor.js`, the same
module FirstPair Reader uses.

**Diff.** When the vault ships precomputed edition diffs
(`_data/triptych-diffs.json`), a **Diff** chip marks what differs between
the editions shown. With two panes the comparison is the pair: struck
through in the earlier edition is what was removed, underlined in the later
is what was added. With three it is the set: highlighted is in that edition
only, underlined in an edition's colour is shared with that edition only.
Hide a pane with its chip to switch from the set to a pair. Tap or hover a
mark for its meaning.

**Kinds of change, history, and rules.** With a version-2 diff file the
pair view adds a row of chips for the kind of change: punctuation, endings,
small words, word choice, restructured, rewritten, added or dropped, and
moved (moved text names the page it went to). The three-pane view adds a
**History** menu: all differences, settled text the latest edition rewrote,
places where the latest went back to the first, or what is new in the
latest. **Review** shows where the edits are, Part by Part, and the **edit
rules**: one-word substitutions that recur across the book, each with
**Accept** (apply everywhere) or **Reject** (keep the earlier word), flagged
when the edit also runs the other way. Rule decisions go to the digest.

**Metrics.** A vault may declare ranked metrics in
`<book>/_data/triptych-metrics.json` (see `publishing/VAULT-CONSTRUCTION.md`).
Each pane shows them as graded chips in rank order; **Settings → Metrics**
hides and reorders them, and **Review → Ranked pages** lists the worst pages
for any metric and edition.

**After the text changes.** Choices made on an earlier text are never applied
to new sentences. Review then offers one scoped action: archive the whole
decision file to `Preferences/archive/` and start a new review.

**Edited copy.** Review → **Edited copy** applies the preferred version of
every saved Edit to one edition and writes Markdown and JSON to
`Preferences/Exports/`. Sources never change.

**Any book.** The plugin finds its book folder on load: `Lighthouse
Republics/` if present, else the first top-level folder holding
`_data/triptych-reader.json` (for example `The Invented Enemy/` in a vault
built by `scripts/build-bilingual-vault.py`). The Reader index's canonical
edition is whichever edition carries its `book_version` and `source_commit`.

All levels are recorded to a durable ledger:

- `Preferences/triptych-decisions.json` — machine-readable decisions, keyed
  by stable fragment, edition, unit, sentence, and quote selectors. Sentence
  IDs carry a normalized prose fingerprint, which is validated before controls
  attach, so a changed sentence cannot silently inherit an old judgment.
  Existing version-1/2 fragment decisions migrate without losing fields. The
  v4 ledger carries project/source identity, Unicode offset semantics, and a
  monotonic review revision; a source mismatch fails closed;
- `Preferences/triptych-decisions.sha256` — exact integrity sidecar for the
  installed JSON ledger;
- `Preferences/EDITING-INSTRUCTIONS.md` — a digest regenerated on every
  change, including whole-pane choices, sentence preferences, Good/Bad/Edit
  phrases, correction histories, preferred variants, and the editor's note.
  It is a decision list for a later editorial pass, never a composed copy.

The vault builder preserves `.obsidian/` and `Preferences/` across rebuilds,
so plugin installation and recorded decisions survive regeneration. The
`Triptychs/` notes themselves are regenerated output; never edit them by
hand.

## Install

```sh
uv run --no-dev python publishing/scripts/bundle-firstpair-triptych.py
uv run --no-dev python scripts/build-obsidian-triptychs.py
```

Distributed vaults intentionally leave community plugins disabled. Enable
**FirstPair Triptych** under Settings → Community plugins after reviewing the
local release.
`main-source.js` and `review-state.js` are the readable sources, with the
shared modules in `../shared/` (ledger store, voice notes, metrics, span
editor). The standard-library bundler deterministically embeds them all in
the single release `main.js` and expands `styles-source.css` (which imports
`../shared/span-editor.css`) into `styles.css`, as required for reliable Obsidian mobile loading. The triptych
builder refreshes only `manifest.json`, bundled `main.js`, `styles.css`, and
this README in the full vault, preserving plugin `data.json`.

## Use

1. Open `Home.md`, then **Open the Triptych Reader** (or use the ribbon or
   command). Pick a set —
   *Edition 4 Decision* is the working set for the fourth edition.
2. Hub notes list every fragment in book order with `P/S/D/A` badges
   (present / same / differs / absent), grouped by part.
3. In a fragment note, read the panes, tick **prefer this** on the pane
   that should win, optionally reveal **Sentence & words**, select phrases
   for finer instructions, and record a compact imperative note, e.g.
   *“keep South's live-oak scene; adopt 3.1's ballot arithmetic.”*
4. Open **Review** to revisit edited pages and inspect the digest. Run
   **Export editing instructions digest** at any time to rewrite
   `Preferences/EDITING-INSTRUCTIONS.md` from the ledger.
